## 作業の順序

1. 未作成 E2E：保存後の読み直し失敗からの再送、各記録経路の確定日時、開いた画面の JST 日付境界。
2. 試験で再現した不具合の修正。保存結果・受付ID・日時を保ち、二重消費や黙ったデータ消失を防ぐ。
3. 固定した実出典の全レシピ・全段階を独立計算した期待値と照合。全件手計算やゲーム内検証とは区別する。
4. Windows にインストール済みの Chrome/Edge での試験、本番成果物の保存・復元・取り込み・画像非表示・外部通信の確認。
5. 既存試験全体、画面比較、typecheck、lint、build、マスター検証を実行し、結果と対象を記録する。
6. 外部確認と実機資料を揃え、公開準備の最終監査、PR、最新 SHA のコード・セキュリティレビューを行う。
