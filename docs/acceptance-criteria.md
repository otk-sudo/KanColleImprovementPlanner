# 受入基準

| ID | 検証すること |
| --- | --- |
| A01 | 取込入力の装備総数・種類数・★別個数が入力から独立集計した期待値と一致。再取込しても倍増しない（R03〜05）。 |
| A02 | 通常ブラウザと74式ENの実レスポンスを各々取り込める。未取得と0を区別し他カテゴリを保持。認証情報を保存しない。 |
| A03 | 未所持装備を目標化できる。未知/未検証条件を不可と誤認せず表示する（R07〜09）。 |
| A04 | 目標の★/個数、段階別・更新分岐・確実化の費用が手計算と一致。素材製作の循環検出、在庫二重使用防止（R09〜12）。 |
| A05 | 艦娘の改造状態ごとの可否と候補、所持不明が正しく表示。未適合は未配置（R13/21）。 |
| A06 | 曜日、休暇、回数上限を守り、資材不足は警告付き仮配置。同日中に自動繰越しない（R14〜17）。 |
| A07 | JSTの日付変更/スリープ復帰/数日ぶり起動で未完了分のみ再配置。再起動や複数タブで重複しない。スキップは無消費。 |
| A08 | 週/月/日別詳細の件数・順序・必要数が一致。予定なし/休み/未配置/仮配置を区別（R18〜19）。 |
| A09 | 成功/失敗/スキップの実績、過去修正、在庫再取込後の再計算で二重減算しない（R20）。 |
| A10 | 保存失敗・破損バックアップ・旧スキーマ・複数タブ・再読込で無言の消失がない（R02/05）。 |
| A11 | WindowsのChrome/EdgeでPC幅と縮小ウィンドウの実操作確認。スマホは対象外。2経路のガイドを実機手順で検証。 |
