# 14 マスター更新・履歴・復元の契約

2026-10-14。R02/R07/R08/R20、A03/A09/A10。設計レビューで確認した「旧版レシピが消えた場合」を補う。

## 版を三種類に分ける

- appVersion：配布したアプリの版。
- schemaVersion：個人DB/バックアップの構造。互換性検証と移行に使う。
- masterVersion：共通装備・艦娘・レシピの内容。各レシピはrecipeIdとrecipeRevisionを持つ。

マスターは内容ハッシュと出典一覧を含む不変の版とし、同じmasterVersionの内容を上書きしない。新しい版のmanifestはschemaVersion、必要なアプリ版、件数、各ファイルのハッシュを持つ。ハッシュは破損検出であり配布元の真正性保証とは呼ばない。

## 過去を表示するための最小保存

実績の確定時にrecipeSnapshotを保存する。入力/出力の装備ID・★、選んだ通常/確実化モード、当時の必要数、実消費、担当艦条件、recipeId/revision、masterVersion、出典IDを含む。表示用の当時の名称も保持する。画像本体・生レスポンスは含めない。

実績画面はこのスナップショットから当時を表示する。新マスターの費用で過去を再計算しない。実際の消費が当時の必要数と異なっても、勝手に書き換えず差として保持する。名称が現在変わっている場合は当時名と現在名を区別する。

未完了工程は旧recipeSnapshotを監査用に残すが、将来実行可否は有効マスターで再検証する。レシピ削除・状態遷移変更・ID不明ならMIGRATION_REVIEW_REQUIREDとして未配置または当日確認待ち。別の更新先へ自動置換しない。

## 更新手順

1. 新マスター全体を別領域へ読み込み、参照整合・数量・曜日/担当艦条件・循環・版/互換性を検証。
2. 変更件数と影響目標・予定をプレビュー。現在利用中の版は保持。
3. 利用者の適用操作でactiveMasterVersionと入力版を原子的に変更し、planDirtyを立てる。
4. 今日の予定は日付を保ち、必要条件・費用を更新。条件が消えたものは確認待ち。将来分を再計算する。
5. 計算失敗なら有効マスターの適用済みと計算待ちを区別し、旧計画を最新と表示しない。

異なるアプリ版のタブが同時に開いている場合、DBのschemaVersionとminimumWriterVersionを更新操作ごとに確認する。古い版が書けない場合は読取専用にし、再読込を案内。revision一致だけで構造互換性を保証しない。DB移行のblocked/versionchange時に他タブを無言で強制終了しない。

## バックアップの必須内容

10の一覧に加えて、工程定義、実績recipeSnapshot、結果下書き、下書き取込境界、範囲別coverage、マスター版参照、保護理由、確実化/素材経路選択を含める。工程定義は結果が参照するものを必須とし、派生カレンダーだけを省略可能とする。

commandReceiptsは通常更新の再送用であり別PCへそのまま移さない。復元時に新しいdatasetEpochを発行し、commandの一意キーを(datasetEpoch,commandId)とする。以前の画面やタブのcommandが復元後に再送されたらepoch不一致で拒否する。実績eventId・originalSequenceは復元して保持し、次のsequenceは保存済み最大値より大きくする。

復元のプレビューは作成日時、件数、現在からの増減、未対応の版、不足するマスターを表示。必要マスターが取得できなくても、正常な個人在庫・履歴は復元可能。ただし計画を「再計算できない」と表示し、現行マスターへの移行が解決するまで自動配置しない。バックアップにマスター参照がない状態を現在版へ黙って置換しない。

破損/不正な参照を含むバックアップは全体拒否。旧データからの移行では、欠落項目に業務上の事実を捏造する既定値を入れない。復元成功後に在庫JSONの境界をリセットしない。

## 検証例

| ID | 条件 | 期待 |
|---|---|---|
| P30 | 過去実績のレシピが新マスターで削除 | 当時の消費を表示可能。将来予定は確認待ち |
| P31 | 旧マスター参照のバックアップを別PCで復元 | 在庫と履歴復元、計画は互換性解決まで未計算 |
| P32 | 復元前画面の保存commandを再送 | datasetEpoch不一致で拒否 |
| P33 | 旧アプリタブが新schemaへ保存 | 版本が合ってもwriter互換性で拒否 |
| P34 | 新マスターファイルの一部破損 | 有効版を変更せず、予定も保持 |

保護は指定値だけでなく、未解消のreconciliationRequired・対象snapshotId・粒度・旧指定もバックアップ対象とする。復元しただけで不一致を解消済みにしない。詳細は06の保護不一致契約。
