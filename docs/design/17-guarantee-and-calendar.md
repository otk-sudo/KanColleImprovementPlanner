# 17 確実化とカレンダー集計の補足

2026-10-14。R10/R18/R19を要求監査で補完。ゲーム条件はレシピに従い、画面の例の数値を条件マスターにしない。

## 確実化規則

目標はguaranteePolicyを持つ。mode=never/always/fromTargetStar、fromTargetStarは1〜10。★6から、という曖昧な表記を使わず「★6になる改修から」と表示する。★5→6は該当、★4→5は通常となる。

更新工程（装備IDが変わる工程）はupdateGuaranteeという独立のbooleanで指定し、更新後★が低いという理由で通常へ戻さない。そのレシピがモードを提供しない場合は選択不可理由を表示する。モードの費用が不明なら0を代入せず条件未確認として扱う。

素材の製作経路は既定で親目標の確実化規則を引き継ぎ、素材経路ごとに上書き可能とする。プレビューは各工程の入力★・出力★・通常/確実化・必要数を列挙。失敗再挑戦は元工程のモードを保持し、利用者が変更した場合だけ再計算する。

保存済み成功/失敗は当時のモードを保持。設定変更は未実施分だけに適用し、今日の予定は日付・順序を保って費用と警告を更新する。設定変更だけで過去消費を変えない。

## 完了予定日の意味

目標が所持品だけで満たされれば「所持で達成」とし、偽の未来予定日を付けない。未完了の全工程が配置済みの場合に最終工程の日付を完了見込み日とする。仮配置が1つでも含まれれば「素材入手を前提とする見込み」と明記。

未配置・条件不明・結果下書きによる保留が1つでもあれば、目標の完了予定日は未定。配置済み部分の最終日を目標全体の完了日として表示しない。各目標へ予約された素材製作工程も含めて評価する。

## カレンダーの件数

日別・週別・月別は同じprojectionから集計する。日付セルの「予定」は有効未実施試行数、「実施」は成功/失敗/実施済み下書きの数、「スキップ」は当日のスキップ数。引継ぎ済み元試行を現在の予定へ重複加算しない。履歴表示では元の日付に残して区別する。

月セルには主装備名、予定件数、仮配置件数、目標完了見込みを表示。溢れは「ほかn件」から日別詳細へ。週表示は工程・★・担当艦・必要素材を要約し、日別詳細で全項目を表示する。

日別の必要数は当日の未実施分、実消費は実施済み分として別表示。過去日の表示で現在在庫を当時の在庫と呼ばない。最新基準より前の在庫を再現する情報が不足すれば「当時の在庫は不明」とする。
