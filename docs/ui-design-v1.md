## UI方針

- 左ナビで主要機能を固定。普段の入口はカレンダー、初回だけS15を表示。
- 色だけで状態を伝えず「仮配置」「不足」「不明」「未所持」「完了」の文字を併記。未取得は0と区別する。
- 資材不足でも同日の予定を保持。日本時間の翌日以降に未実施を確定してリスケ。閉じている間の遅れは再起動時に一度だけ処理。スキップも同じ翌日判定で、消費・改修値の変更なし。
- 担当艦未所持・必要改造段階未達・条件不明は未配置一覧に理由を表示。資材不足の仮配置と混ぜない。
- 目標登録時に既存完成品・残工程・不足をプレビュー。達成品と改修対象を素材に二重割当しない。
- 取り込みは種類別の置換。反映前に取得日時・件数・差分を見せ、ない種類の既存情報は保持。元レスポンスを送信するサーバーは設けない。
- 実績は明示的に入力。取り込み後の在庫に過去の消費を再減算しない。修正時は在庫・後続予定への影響を確認してから保存。
- バックアップはバージョン・日時・範囲を検証し、復元前の保存を案内。失敗時は現在状態を保持。

## PCウィンドウ幅とアクセシビリティ

1440pxボードは基準寸法であり固定幅実装を要求しない。初稿での提案：1280px以上は日別詳細を横に並べ、1024〜1279pxでは詳細をオーバーレイまたは独立ビューにする。表は列を潰さず必要なら横スクロール。スマートフォン向け仕様は対象外。

通常本文14〜16px、見出し18〜28px、補足12〜13px、操作対象の高さ40px以上。実装ではキーボード操作、明確なフォーカス、日付セルの読み上げ、エラーと入力欄の関連付け、選択状態の読み上げを用意。色のコントラストと200%拡大時の操作性は実装後に検証する。

色：背景 #F3F6F7、ナビ #152F39、本文 #18313B、補足 #637680、主操作 #087F80、淡い強調 #E4F3F0、不足背景 #FFF3D9・文字 #94600A、エラー背景 #FCEDEB・文字 #A23830。

## 補完した操作仕様（レビュー第4巡）

以下は静止画に含まれない条件分岐も含む画面の動作契約。製品実装は静止画のボタンの見た目だけで判定しない。

### PC幅・キーボード・共通状態（R01）

- 1440pxを基準、1280px以上は左ナビ216px＋本文。1024〜1279pxではナビを折り畳み、2列フォームを1列へ。1024px未満のPCウィンドウでも操作できるよう日別詳細はカレンダーの下へ移す。表だけ横スクロールを許可し、画面全体の横スクロールに操作ボタンを追い出さない。スマホ専用UIは作らない。
- 1280×720、1024×768、ブラウザ200%拡大でラベル・エラー・保存/戻る操作を確認する。固定1440px座標をそのまま絶対配置しない。
- 入力→エラー→主操作の自然なTab順。フォーカス可視、ボタンのEnter/Space操作、ダイアログはフォーカスを内部へ移し、閉じると起点へ戻す。Escは未保存変更がなければ閉じ、ある場合は破棄確認。
- 画像だけの操作は禁止。正式名称と状態文字を併記。エラーは該当入力へ関連付け、色だけで不足/不明を区別しない。
- 保存中は重複確定を無効化。保存失敗は入力を保持して再試行。版競合時は他タブ変更を表示して最新プレビューへ戻す。0件、読込中、条件不明、計算待ちを別表示する。

### 保護再照合（S06、R12）

取り込みで個体入力と集計入力が切り替わる、または保護数が最新所持を上回る場合、S06の先頭に「保護設定の確認が必要」を表示。対象の装備名/★、旧所持、最新所持、手動保護、目標由来保護を並べる。

操作は「最新所持のどれを保護するか選択」「手動保護数を変更」「今は保留」。保留でもJSON反映を巻き戻さない。その装備を新たに素材へ割り当てず、影響計画は確認待ち。数量が一致しても個体対応は推測せず、集計枠として保護するか明示する。目標由来保護の変更は目標編集へ誘導し、手動保護と二重加算しない。

### 過去実績のscope別扱い（S09→S13→S29、R05/R20）

実施日が過去、または取り込み後の記録漏れを選んだ場合、確認画面に装備/資材/その他アイテム別の「現在の基準を取り込んだ日時」「今回の実績を履歴のみとするか」「現在数の変更前後」を表示。日時不明を0時などに捏造しない。

保存済みイベントの訂正でscopeのoriginalSequenceが基準以前なら履歴のみ固定。取り込み後に初めて追記する記録漏れでは、利用者が各scopeの実績が最新基準より前かを確認する。対象が複数scopeでも1つの回答を全種類へコピーしない。これはJSONの新旧を選ばせるものではなく、追記する実績の適用範囲の確認。

未回答scopeがある場合は下書き可能、実績確定不可。結果下書きが新JSONへincludedDraftIdsで包含済みのscopeは履歴のみ固定とし再質問しない。後継結果との矛盾があればS29で対象を列挙して、一括訂正が整合するまで保存不可。

### 確認待ち記録の再開・取消（S09/S28、R20）

一覧に実施日、装備/★、報告結果、未確定項目、在庫保留中の種類を表示。「再開」はS13へ入力値を引き継ぐ。「実施していなかった」は理由必須の確認ダイアログを開き、日別回数・保留・後続予定の変化を表示して確定。単なる「削除」で履歴を消さない。

S28の保存は実施済みチェック後のみ可能。結果未選択ならS13へ戻す。再開から確定しても実施回数を追加しない。閉じるだけでは下書きを消さない。新JSONのscope包含後も下書き自体は履歴確認のため残すが、そのscopeの在庫保留は解除する。

### マスター不足時の復元（S21、R02）

復元プレビューにschemaVersion、必要マスター、利用中マスター、互換性、データ件数を表示。構造検証済みだが必要マスターがない場合は「在庫と履歴は復元可能／予定計算は保留」と表示。

操作は「戻る」と「計算保留を確認して復元」。確認チェック前は復元不可。成功後は所持・履歴を利用可能とし、カレンダーに「マスターを確認して再計算」の案内。破損・未知schemaは同じ画面でも復元不可で、部分復元しない。必要マスター不足と破損を同じエラーにまとめない。

### 担当艦候補（S18→S19、R13/R19）

担当艦表示を開くと、選択日の曜日に対応する全候補を正式名・改造段階・所持数・適合理由付きで列挙。所持適合候補を選択可能。不明と未所持を分ける。選択はその工程の希望担当艦として保存し、再取り込みで不適合になったら警告して再選択を促す。自動候補を使う選択も用意する。

希望担当艦が不適合なら別候補へ黙って切り替えず確認待ちにする。希望指定なしは09の安定順で自動選択。担当艦の現在の遠征等を未取得なら実行可能とは断定しない。

### 第12巡：S34の過去実績確認
S34は過去実績追記の未回答状態。各scopeは「所持数に反映」「履歴だけに記録」のラジオ選択とする。取込日時から自動選択せず、利用者の明示回答を保存。包含済みの訂正や下書きscopeは履歴のみ固定・理由併記。選択に応じて現在数の前後を再計算し、全回答かつ数量・後継整合が成立した場合だけ確定を有効にする。

未回答で確認待ちへ進む場合、reportedOutcome、既知消費、各scopeの回答、未回答scopeを保持する。successをfailureへ変更しない。包含済みまたは履歴のみと明示したscopeは新たな保留を作らず、適用未回答のscopeは充足を断定しない。S28の静止画は別例なので文言や値をそのままコピーしない。
